# SchoolMitra Product Destination

## The Destination Sentence
> **"One real school, 500-2000 students, one board, one state, runs one full academic term entirely on SchoolMitra: zero Excel registers, zero untracked phone calls, fee cycle closed monthly, attendance under four minutes per section, exams conducted end to end with published results — and the school renews and refers another school."**

---

## In-Product Destination
Every journey **J1 through J10** defined in the [Product Destination Charter](file:///v:/Cascade/2026/Edu_core/docs/product-destination-charter.json) is walkable end to end by its corresponding persona, with an explicit, visible finished state rendered to the user, and verified continuously by an automated walkthrough test suite.

## What Destination Is Not
- **Not more modules**: Adding new loosely coupled feature areas dilutes focus and increases support burden.
- **Not more role apps**: The ten existing role applications are sufficient for the school's operational perimeter.
- **Not more superficial certifications**: Passing a checklist without operational fidelity does not close a school day.
- **Scope rule**: If a proposed task does not directly advance a journey toward its verified finished state, it will not be built.

---

## Charter Amendment Protocol
This governing charter changes exclusively through an explicit git commit modifying this document, accompanied by an amendment justification recorded in the log below. New journeys may be added only when they specify:
1. Primary Persona
2. Explicit Trigger
3. Clear Finishable Steps
4. Visible Finished State
5. North Star Metric linkage
