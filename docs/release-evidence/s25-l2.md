## 1. Summary of Changes

Layer L2 eliminates flaw **S25-F01** by making the SMS queue drain worker honest and functional:

1. **Dead Import Activated**:
   - Replaced dead `sendSMS` import in `backend/src/workers/notificationQueueWorker.ts` with `sendSMSWithStatus`, the production Indian DLT / international gateway service with retry resilience.
2. **Recipient Mobile Number Decryption**:
   - For every queued SMS row, queries the recipient user or family member linkage (`users.mobileEncrypted`, `studentFamilyMembers.mobileEncrypted`), and decrypts via `decryptData`.
   - If no mobile number is found, marks the log as `FAILED` with `failureReason: "No mobile number on file for recipient"` without counting toward the daily cap.
3. **Strict Downstream Status Transitions**:
   - `delivered === true`: transitions to `status: "SENT"`, saves `gatewayMessageId`, sets `sentAt: new Date()`, increments `sentCount`, and decrements `remainingCap`.
   - `delivered === false` (gateway error): transitions to `status: "FAILED"`, records `failureReason: result.error`, sets `sentAt: new Date()`, does not count toward daily quota.
   - `unconfigured === true` (OD2): defers honestly in `QUEUED` state without consuming daily quota and without fabricating `SENT`.
4. **500 SMS/Day Quota Preservation**:
   - Only counts actual `SENT` rows toward the daily 500 limit. If cap is exhausted, subsequent rows are not processed and tallied as `cappedCount`.
