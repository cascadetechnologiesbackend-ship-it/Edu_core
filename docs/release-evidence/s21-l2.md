## 2. Invariants & Database Integrity

### 2.1 Unique Constraint Preservation (`bell_schedule_school_period_unique`)
- In `database/src/schema/academics.ts`, `bell_schedule` enforces `unique("bell_schedule_school_period_unique").on(t.schoolId, t.periodNumber)`.
- In `canonicalBlueprints.ts`, `STANDARD_SECONDARY_BELL_SCHEDULE` contains break periods with `periodNumber: 0` (`ASSEMBLY`, `SHORT_BREAK`, `LUNCH_BREAK`).
- Both `executeProvisionSchool` and `topUpSchoolProvision` filter `periods` for `periodNumber > 0` (instructional and activity periods 1..N).
- Breaks are modeled as duration gaps between instructional periods, preventing unique constraint violations.
- When existing periods are found with `isActive === false`, they are reactivated via `.update(bellSchedule)` instead of re-inserted, preventing duplicate key violations.

### 2.2 School Provisions Lock (`sp_school_unique`)
- `school_provisions` table enforces `unique("sp_school_unique").on(t.schoolId)`.
- `executeProvisionSchool` creates the initial provision lock.
- `topUpSchoolProvision` strictly performs `.update(schoolProvisions)` on `entityCounts` (`bellSchedule: totalPeriods`, `bellSchedulePeriods: totalPeriods`) rather than inserting a duplicate record, preserving audit provenance and honoring the idempotency lock.

### 2.3 Mobile 390px Zero Horizontal Overflow
- `SchoolProvisionModal.tsx` uses `grid-cols-2 sm:grid-cols-4 gap-2.5` for prospective counts and success metrics, reflowing into a 2x2 grid on 390px mobile viewports without horizontal scrolling.
