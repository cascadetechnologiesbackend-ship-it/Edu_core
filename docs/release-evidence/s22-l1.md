## 2. Delivered Architectural Components

### 1. Authoritative Domain Engine (`backend/src/lib/communicationLoop.ts`)
- **`resolveChildTeachers`**: Discovers active homeroom and subject teachers for parent's children. Joins `classes`, `sections`, `class_subjects`, `subjects`, `persons`, and `users`. Filters out expired allocations (`effectiveTo < today` or `isActive = false`).
- **`validateMessageRecipient`**: Enforces that parents cannot message unassigned teachers, and teachers cannot message unassigned parents. Validates thread reply participant continuity.
- **`getParentConversations`**: Groups incoming and outgoing messages by thread (`parentMessageId || id`), computes per-thread `unreadCount` (`recipientUserId = parentUserId AND isRead = false`), resolves counterpart teacher names and roles.
- **`getTeacherConversations`**: Scoped strictly to teacher's active section allocations.
  - **Displacement Law Invariant**: If a teacher's allocation is revoked, conversations for students in that section immediately vanish from the teacher's inbox.
- **`getThreadMessages`**: Chronological message timeline with participant verification (or Principal/Admin moderation check).
- **`markThreadRead`**: Transactional read receipt updater setting `isRead = true` and `readAt = now()` for the recipient.
- **`getAdminModerationConversations`**: Read-only school-wide thread list that records a forensic audit log entry in `audit_logs`.

### 2. Parent Server Actions (`frontend/src/app/(parent)/parent/messages/actions.ts`)
- Hardened `sendParentTeacherMessage` with `validateMessageRecipient` to prevent raw user ID injection.
- Preserved single canonical write path for both Parent and Teacher applications.
- Exposed `resolveChildTeachersAction`, `getParentConversationsAction`, `getThreadMessagesAction`, `markThreadReadAction`, and `getAdminModerationConversationsAction`.

### 3. Teacher Server Actions (`frontend/src/app/(teacher)/teacher/messages/messagesActions.ts`)
- Re-exports `sendParentTeacherMessage`, `markThreadReadAction`, and `getThreadMessagesAction` to eliminate write-path forking.
- Exposes `getTeacherConversationsAction` strictly scoped to active allocations.
