## 1. Summary of Changes

Layer L1 addresses flaws **S25-F04** and **S25-F05** by eliminating simulated success states in unconfigured environments and rebuilding the Web Push live path to comply with the official Web Push Protocol (RFC 8030, RFC 8291 `aes128gcm` encryption, RFC 8292 VAPID authentication):

1. **Dependency Installation (OD1)**:
   - Added standard `web-push` (`^3.6.7`) and `@types/web-push` (`^3.6.4`) to `@schoolmitra/backend`.
2. **Honest Configuration & Mock Guard**:
   - Added `isWebPushConfigured(): boolean` verifying presence of both `NEXT_PUBLIC_VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY`.
   - Replaced unconditional simulated delivery with `SKIPPED_UNCONFIGURED` (`success: false`, honest error reason).
   - Enforced strict mock gate: simulated delivery permitted *only* when `ALLOW_MOCK_PUSH="true"` in development/test. In production (`NODE_ENV === "production"`), mock push is hard-blocked and throws a fatal error unless `ALLOW_MOCK_PUSH_IN_PROD="true"` is set.
3. **Official Web Push Protocol Live Path**:
   - Live dispatch now passes standard VAPID headers (`webpush.setVapidDetails`), encrypts payload with subscription keys (`p256dh`, `auth`), and sets standard TTL and urgency options.
4. **Subscription Pruning on 404/410**:
   - Automatically deletes expired/unregistered subscriptions from `userPushSubscriptions` when the push service returns HTTP `404 Not Found` or `410 Gone`.

## 4. Honest Limitations & Notes

- Real push delivery requires schools or deployments to generate and set valid VAPID keys:
  ```bash
  npx web-push generate-vapid-keys
  ```
  Set `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, and `VAPID_SUBJECT` in the environment.
- In test environments without real FCM or Mozilla push endpoints, tests mock `web-push.sendNotification` to assert protocol compliance.
