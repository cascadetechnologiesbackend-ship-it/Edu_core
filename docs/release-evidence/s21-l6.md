## 2. Diagnostics & Root Cause Analysis

### 2.1 Missing `classTeacherAssignments` Mock
During Sprint S20 ClassHub implementation, `checkClassTeacherAssignmentConflict` was introduced at line 63 of `frontend/src/app/(admin)/academics/actions/teacher-assignment.actions.ts`:
```typescript
const conflict = await db.query.classTeacherAssignments.findFirst({
  where: and(
    eq(classTeacherAssignments.schoolId, schoolId),
    eq(classTeacherAssignments.academicYearId, academicYearId),
    eq(classTeacherAssignments.teacherId, teacherId),
    eq(classTeacherAssignments.isActive, true)
  )
});
```
Because `classTeacherAssignments` was not present in the mock query objects of the test files, execution failed with:
```
TypeError: Cannot read properties of undefined (reading 'findFirst')
```

### 2.2 Missing `sections.findMany` Mock
In `setClassSubjectLead` at line 407 of `teacher-assignment.actions.ts`:
```typescript
const sectionsList = await tx.query.sections.findMany({
  where: and(
    eq(sections.schoolId, schoolId),
    eq(sections.classId, classSubject.classId),
    eq(sections.isActive, true)
  )
});
```
The test mock for `tx.query.sections` only defined `findFirst`, not `findMany`, failing with:
```
TypeError: tx.query.sections.findMany is not a function
```

### 2.3 Store Propagation in `classHubAssignmentE2E`
The chainable `set` handler in `classHubAssignmentE2E.test.ts` failed to update `store.classSubjects` when `assignedTeacherId` was modified, and failed to update `store.sections` when `classTeacherId` or `name` was set. In addition, `returning` and `values` for `insert-sst` required guarding against undefined `classSubjectId`.
