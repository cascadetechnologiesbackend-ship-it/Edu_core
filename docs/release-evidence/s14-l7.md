## 1. Implementation Summary

1. **RBAC Guard Matrix (`frontend/src/app/(admin)/academics/__tests__/assignmentRbacAndIsolation.test.ts`)**:
   - Comprehensive permission probe verifying that teacher assignment write operations (`saveSection`, `batchUpdateClassSubjectMappings`, `assignSectionTeacher`) strictly enforce required roles `["SUPER_ADMIN", "SCHOOL_ADMIN", "PRINCIPAL"]`.
   - Verified that denied roles (`TEACHER`, `HR_MANAGER`, `ACCOUNTANT`, `STUDENT`, `PARENT`, `DRIVER`) fail closed with `FORBIDDEN: requires roles [SUPER_ADMIN, SCHOOL_ADMIN, PRINCIPAL]`.
   - Verified that unauthenticated calls without an active session fail closed with `UNAUTHORIZED`.
   - Verified that allowed roles (`SUPER_ADMIN`, `SCHOOL_ADMIN`, `PRINCIPAL`) execute and return `{ success: true }`.

2. **Multi-Tenant Two-School Isolation Probe**:
   - Simulated two distinct schools (`school-A` and `school-B`) with independent faculty rosters, classrooms, sections, and subject allocations.
   - **Teacher Roster Isolation**: `getTeachersList()` executed under `school-A` context returns solely School A teachers and zero teachers from School B. Executed under `school-B` context returns solely School B teachers.
   - **Cross-School Class Mutation Boundary**: School A admin attempting to call `saveSection` with `classId: "class-B1"` (belonging to School B) fails closed with `"Invalid class specified"`.
   - **Cross-School ClassSubject Mutation Boundary**: School A admin attempting to call `assignSectionTeacher` with `classSubjectId: "cs-B1"` (belonging to School B) fails closed with `"Invalid class subject specified"`.
   - **Cross-School Section Mutation Boundary**: School A admin attempting to call `assignSectionTeacher` with `sectionId: "sec-B1"` (belonging to School B) fails closed with `"Invalid section specified"`.
   - **Multi-Tenant Batch Mutation Boundary**: Calling `batchUpdateClassSubjectMappings` under `school-A` strictly scopes `withTenant` to `"school-A"` and filters all removals/updates by `schoolId: "school-A"`.

3. **Parent PWA Hydration Mismatch Hardening (`NoticeCard.tsx`, `HomeworkCard.tsx`, `PTMCard.tsx`)**:
   - Resolved client-server date format mismatch on Parent PWA notice feed cards ("22 Oct" vs "Oct 22") by using deterministic `MONTH_NAMES` indexing and `suppressHydrationWarning` on date display spans.
