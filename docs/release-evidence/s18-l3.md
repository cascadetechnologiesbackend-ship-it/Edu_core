## 1. Displacement Capture & Dual Eviction Invariant

In all teacher assignment mutation actions:
1. **`setClassSubjectLead`** (`frontend/src/app/(admin)/academics/actions/teacher-assignment.actions.ts`)
2. **`upsertClassTeacherAssignment`** (`frontend/src/app/(admin)/academics/actions/teacher-assignment.actions.ts`)
3. **`hrAssignClassTeacher`** (`frontend/src/app/(admin)/hr/actions.ts`)
4. **`hrAssignSubjectTeacher`** (`frontend/src/app/(admin)/hr/actions.ts`)

The prior active lead or class teacher (`oldTeacherId` / `priorActiveTeacherId`) is captured before updating the record.
Upon successful transactional commit, the cache eviction sequence runs:
```ts
// 1. Evict dropdown picker cache
await invalidateTeachingStaffCache(schoolId);

// 2. Evict displaced teacher cache explicitly
if (priorActiveTeacherId && priorActiveTeacherId !== newTeacherId) {
  clearTeacherScopeCache(priorActiveTeacherId);
}

// 3. Evict incoming teacher cache explicitly
if (newTeacherId) {
  clearTeacherScopeCache(newTeacherId);
}

// 4. Broad flush to ensure multi-threaded / instance consistency
clearTeacherScopeCache();
```
