## 1. Implementation Summary

### 1. Resolver Hardening (`frontend/src/app/(admin)/hr/teachingStaff.ts`)
- Updated `CanonicalTeacher` interface to include `classificationConflict?: boolean`.
- In `getCanonicalTeachingStaff`, modified the fallback loop over users holding the `TEACHER` role:
  - If a user holds the `TEACHER` system role and is linked to an active staff profile whose designation has `isTeaching === false`, they are now **included** in the teaching faculty array instead of being dropped via `continue`.
  - Their record is marked with `classificationConflict: true` and populated with their decrypted name and employee code.
  - Staff who hold non-teaching roles (e.g. `ACCOUNTANT`, `DRIVER`) without `isTeaching` continue to be strictly excluded.
  - Fallback seed/test accounts holding `TEACHER` role without a staff profile continue to be supported with `classificationConflict: false`.

### 2. Diagnostics Server Action (`frontend/src/app/(admin)/hr/actions.ts`)
- Added `getTeachingStaffDiagnostics(schoolId?: string)` guarded for roles `SUPER_ADMIN`, `SCHOOL_ADMIN`, `PRINCIPAL`, `HR_MANAGER`.
- Returns:
  - `activeStaffCount: number`
  - `isTeachingCount: number`
  - `teacherRoleCount: number`
  - `conflictCount: number`
  - `conflicts: Array<{ staffId, userId, employeeCode, designationId, designationName }>`

### 3. HR Designations Conflict Banner (`frontend/src/app/(admin)/hr/tabs/DesignationsTab.tsx`)
- Fetches diagnostics on render.
- When `conflictCount > 0`, renders an actionable amber banner identifying the affected staff members and employee codes.
- Provides a one-click *"Fix: Mark '[Designation]' Teaching"* action that immediately invokes `updateDesignation(id, { isTeaching: true })` and refreshes the view.
