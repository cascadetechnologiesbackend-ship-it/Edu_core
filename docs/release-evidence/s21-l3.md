- **F11: Timetable Deterministic Preview Server Action (`generateSectionTimetablePreview`)**:
  - Implemented in `frontend/src/app/(admin)/academics/actions/timetable.actions.ts`.
  - Queries active `bellSchedule`, `classSubjects`, `sectionSubjectTeachers`, and existing `timetablePeriods` for `sectionId` within tenant session context.
  - Executes `validateWorkloadFit` verifying weekly periods vs capacity.
  - Executes `generateDeterministicSchedule` with anti-fatigue dispersion (max 2 periods/day for any subject) while locking in existing manual overrides intact.
  - Implements unique teacher auto-assignment rule: auto-assigns teacher if and only if exactly 1 active allocation in `sectionSubjectTeachers` for `(classSubjectId, sectionId)`. If 0 or > 1 allocations, leaves teacher unassigned and records in `needsAssignmentReport` with reason (`NO_ALLOCATION` or `AMBIGUOUS_MULTIPLE_ALLOCATIONS`).
  - Executes `checkScheduleClashes` verifying cross-class teacher double-booking and room overlap concurrency against other sections.
  - Returns `{ fits, fitReport, slots, clashes, needsAssignmentReport, unassignedPeriodsCount }`.

- **F12: Timetable Commit Server Action (`commitSectionTimetable`)**:
  - Implemented in `frontend/src/app/(admin)/academics/actions/timetable.actions.ts`.
  - Routes slot persistence exclusively through existing conflict-enforced `saveTimetablePeriod` (generator never writes direct SQL to `timetablePeriods`, ensuring full conflict checks and authorization).
  - Preserves existing slots where `isManualOverride === true` (never overwrites or deactivates manual overrides).
  - Deactivates orphaned non-manual periods not present in new generated slots (`isActive = false`).
  - Re-exported via `frontend/src/app/(admin)/academics/actions.ts`.
  - Returns `{ success: true, upsertedCount, deactivatedCount, preservedOverridesCount }`.

  - Implemented `AppModal size="2xl"` rendering:
    - 3-stat workload fit feasibility card (available periods, required periods, slack/deficit, subject breakdown).

  - "Confirm & Apply" action dispatching to `commitSectionTimetable` and rendering server-confirmed persistence metrics.

## 2. Invariants & Architecture

### 2.1 Conflict-Enforced Single Write Path
- Automated schedule generator never executes raw SQL inserts on `timetablePeriods`.
- Every generated period is routed through `saveTimetablePeriod`, inheriting teacher double-booking checks, room concurrency checks, classroom subject mapping validation, and tenant isolation.

### 2.2 Manual Override Invariant
- Slots manually saved by administrators are tagged with `isManualOverride = true`.
- During automated schedule regeneration, manual overrides are loaded first into `generateDeterministicSchedule({ existingSlots })` and excluded from `commitSectionTimetable` orphan deactivation.

### 2.3 Strict Unique Teacher Allocation Rule
- Auto-assigns teacher if and only if `activeAllocations.length === 1`.
- If 0 allocations or ambiguous (> 1 allocations), slot teacher is left unassigned (`teacherId: null`) and surfaced in `needsAssignmentReport`.

### 2.4 Deactivated Slot Reactivation (Constraint Bug Prevention)
- `timetablePeriods` enforces `UNIQUE("section_id", "day_of_week", "period_number")`.
- When updating or re-generating a timetable, `saveTimetablePeriod` searches for existing slots regardless of `isActive` status, reactivating inactive rows via `UPDATE` rather than attempting a duplicate `INSERT`.
