## 3. Sprint 21 Flaw Inventory & Root-Cause Audit

### S21-F01: Baseline Vitest Academics Mocks Failing
- **Investigation**: `checkClassTeacherAssignmentConflict` added in S20 queried `db.query.classTeacherAssignments.findFirst`, and `setClassSubjectLead` queried `tx.query.sections.findMany`. The unit test mocks in `assignmentPopulationE2E`, `classHubAssignmentE2E`, and `classHubAssignmentSurfaces` lacked definitions for these tables/methods.
- **Verdict**: **MOCK DEFECT**. Repaired in Layer L6.

### S21-F02: `executeProvisionSchool` Omits Bell Schedule Periods
- **Investigation**: Canonical blueprints define rich bell schedules with 6–8 periods per day. `executeProvisionSchool` cloned classes, sections, subjects, fee heads, departments, salary templates, and holidays, but completely skipped `bellSchedule`. Schools provisioned had 0 periods.
- **Verdict**: **PROVISIONING DEFECT**. Resolved in Layer L2.

### S21-F03: Missing Top-Up Provisioning Action for Already-Provisioned Schools
- **Investigation**: Schools provisioned prior to S21 possessed no periods. Re-running `executeProvisionSchool` threw a unique violation on `school_provisions.schoolId` (`sp_school_unique`). No scoped top-up capability existed.
- **Verdict**: **FEATURE DEFECT**. Resolved in Layer L2 with `topUpSchoolProvision` and `topUpSchoolProvisionAction`.

### S21-F04: Dry-Run Preview Missing Bell Schedule Metrics
- **Investigation**: `dryRunProvisionSchool` reported existing/prospective counts only for classes, subjects, fee heads, and departments. Bell schedule was invisible to super admins.
- **Verdict**: **UX DEFECT**. Resolved in Layer L2.

### S21-F05: Simulated Import Commits with `setTimeout`
- **Investigation**: `ImportExportModal.tsx` simulated import commit via client-side `setTimeout(1500)` rather than invoking a real domain transaction, violating Honesty Law AC-5.
- **Verdict**: **HONESTY DEFECT**. Scheduled for Layer L1.

### S21-F06: Timetable Generator Detached from Timetable Builder UI
- **Investigation**: `timetableEngine.ts` contained deterministic scheduling logic, but the QuickTimetable builder UI provided no generation trigger or preview modal.
- **Verdict**: **WIRING DEFECT**. Scheduled for Layer L3.

### S21-F07: Setup Hub Reports 100% Health for Schools with Zero Operational Readiness
- **Investigation**: `getSchoolConfigurationHealthAction` tracked only configuration milestones. A school with 0 periods, 0 timetable slots, and 0 students could report 100% setup completeness.
- **Verdict**: **HONESTY DEFECT**. Scheduled for Layer L4.

### S21-F08: `setupSchool` Permitted Duplicate Active Academic Years
- **Investigation**: Re-running setup or adding academic years did not deactivate previous active years, creating ambiguity in timetable and attendance resolution.
- **Verdict**: **DATA INTEGRITY DEFECT**. Scheduled for Layer L4.
