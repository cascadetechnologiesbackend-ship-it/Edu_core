## 2. Invariants & Security Architecture

### 2.1 Single Authoritative Write Path (`scripts/audit-lifecycle-hygiene.mjs`)
- Direct `.insert(students)` is strictly prohibited across all frontend and backend application code outside of `backend/src/lib/studentLifecycleEngine.ts`.
- `commitStudentImportAction` never inserts into `students` directly; all student records are channeled exclusively through `StudentLifecycleEngine.createImportedStudent`.
- Static analysis guard `node scripts/audit-lifecycle-hygiene.mjs` runs with 0 violations.

### 2.2 Fail-Closed Tenant Isolation & Session Integrity
- Server actions derive `schoolId` strictly from `requireAuth` and `requireSchool(ctx)` server session. No client-supplied school IDs are accepted.
- All transactional modifications run inside `withTenant(schoolId, async (tx) => ...)`, executing `set_config('app.current_school_id', schoolId, true)` for PostgreSQL Row-Level Security (RLS) enforcement.

### 2.3 DPDP Act 2023 Compliance & IP Sanitization
- Client IP addresses are extracted via `getClientRequestContext()`.
- Loopback addresses (`127.0.0.1`, `::1`) are sanitized to `"0.0.0.0"` in compliance with Layer 7 IP hygiene guards.
- Consent records for mandatory statutory purposes (`admission_data`, `academic_records`) are recorded with truthful sanitized client IP and `method: "admin_attestation"`.

### 2.4 All-or-Nothing Transactional Semantics (PF-R100)
- All rows are verified in memory and against tenant curriculum prior to opening the database transaction.
- If a single row fails schema validation or class/section resolution, the action aborts immediately, commits 0 rows, and returns line-numbered rejected CSV.
- When all rows are valid, the transaction executes atomically, skipping already existing unique keys without throwing duplicate key exceptions.

### 2.5 PostgreSQL Schema Constraints & Role Enum Alignment
- Enforces strict NOT NULL constraints in database transactions:
  - `persons.gender`: Guaranteed non-null with valid enum or `"OTHER"` default.
  - `staff.dateOfBirthEncrypted`: Guaranteed non-null with AES-256 encrypted string.
  - `staff.genderEncrypted`: Guaranteed non-null with AES-256 encrypted string.
- System Role Guarding: General staff (`STAFF`) map to `persons.primaryType = "STAFF"` and `designations.mappedRole = "STAFF"`, while `roles` / `userRoles` table insertions are strictly guarded to valid system enum values (`TEACHER`, `ACCOUNTANT`), preventing PostgreSQL `invalid input value for enum role_name: "STAFF"` crashes.
