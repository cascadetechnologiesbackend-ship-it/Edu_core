## 2. Key Delivered Architectural Components

### 1. Push Dispatch & Policy Engine (`backend/src/lib/communicationLoop.ts`)
- **`isMessageQuietHours(date, timeZone)`**:
  - Enforces `21:30 - 07:00` (Asia/Kolkata) quiet window.
- **`dispatchMessagePushNotification(schoolId, senderUserId, recipientUserId, subject, contentSnippet, options)`**:
  - Checks quiet hours; inserts audit record with status `SKIPPED_QUIET_HOURS` if active.
  - Queries `push_notification_logs` for today's deliveries; inserts `SKIPPED_DAILY_CAP` if $\ge 5$ pushes have occurred.
  - Resolves sender's display name and dispatches via `dispatchWebPush`.
  - Records delivery outcome (`DELIVERED`, `SKIPPED_NO_SUBSCRIPTION`, or `FAILED`) into `push_notification_logs`.

### 2. Single Write-Path Integration (`frontend/src/app/(parent)/parent/messages/actions.ts`)
- Calls `dispatchMessagePushNotification` non-blockingly upon successful message insertion.
- Triggers instant cache revalidation across 4 surfaces:
  - `/parent/messages`
  - `/teacher/messages`
  - `/parent/dashboard` (Parent companion home feed)
  - `/teacher/dashboard` (Teacher educator home feed)

### 3. Educator Feed Truth (`backend/src/lib/teacherEventEngine/snapshotAssembler.ts`)
- Replaces generic placeholders with truthful student decryption (`firstNameEncrypted`, `lastNameEncrypted`) and section resolution.
- Derives `MessagesCard` with `tier: "T2_informational"` displaying unread parent inquiries, deep-linking directly to `/teacher/messages`.

### 4. Parent Companion Feed Truth (`backend/src/lib/parentEventEngine/deriveParentFeed.ts`)
- Derives `MessageCard` for each unread message thread from teachers with teacher name and message snippet, deep-linking to `/parent/messages?thread={threadId}`.

## 4. Invariants & DPDP Compliance

- **Quiet Hours Invariant**: No push notifications dispatched between 21:30 and 07:00 IST.
- **Daily Cap Invariant**: Max 5 pushes/day per recipient.
- **Audit Logging**: All suppressed and delivered push attempts logged to `push_notification_logs`.
- **Zero New Dependencies & Zero Schema Migrations**: Completed using existing tables (`push_notification_logs`, `parent_teacher_messages`) and standard Web Push infrastructure.
